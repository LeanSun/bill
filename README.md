# 轻账 · 收支看板

个人账单可视化面板。**2022 — 2026 五年、2958 笔流水**，全部跑在一个静态页里 —— 无构建、无依赖、无数据库。

打开 `index.html` 即可用。要跨设备共用一份账，附带一个零依赖的 Node 后端（`server/`），单进程同时发站点和 API。

线上：<https://leansun.github.io/bill/>

---

## 界面

两个视图，侧栏切换：**总览** 与 **日历**，**打开默认落在日历**（无 hash 时自动补 `#/calendar`）。旧的 `#/analysis`、`#/stats`、`#/trend` 深链仍可用，一律折到总览页。侧栏是三个同款全宽号按钮竖着排：蓝色「记一笔」，下面跟着**同宽同高的「深浅切换」和「配色」**（各 38px 高、图标 + 文字居中），底部再一行「云同步」；窄屏（≤940px）侧栏折成横条，这三颗按钮收成 36px 图标，云同步改由同排的云图标进入。

页面顶部不再有标题行：正文从 18px 留白起排，日历因此能多吃约 70px 的高度。侧栏宽 208px，右侧内容区按视口自适应铺满。

**总览** —— 顶部一条四格信息带（收入 / 支出 / 结余 / 储蓄率，各带同比、月均日均、笔数与 12 个月走势线），下面是七张图：月度收支趋势、支出构成、结余变化、**体重记录**（时间轴，带平均线和最新 / 区间 / 较首次变化）、消费日历热力、分类走势堆叠、高频项目 TOP 10。再往下是**四张各自独立的魔方数字卡**（收藏 / 购买记录、魔方相关支出、参赛次数、比赛报名费）和**两张魔方图**（年度购买趋势、类型支出排行，后者是和高频项目 TOP 10 同款的横向柱），最后是两张各自独立的整宽卡 —— **社保** 与 **报销费用**，不挤在同一张卡里，各管一件事，各自可单独拖拽、单独调宽高。切换视图时全部图一起重绘。

**配色自定义** —— 侧栏「配色」打开面板，五个支出分类 + 收入各一颗色块，HEX / RGB 双向同步。`palette()` 每次渲染都从 `:root` 的 `--cat-*` 读值，所以改一处，图表、筛选胶囊、格子里的条目、天页分类色一起跟着换。现在这套 —— 餐饮 `#FFC000`、日常 `#490033`、交通 `#264465`、服饰 `#8B5CF6`、娱乐 `#0000E4`、收入 `#E04A4A` —— 就是出厂默认，点「恢复默认」回到它。深色主题下亮度过低的自定义色会自动向白色混 48%，免得紫红在暗底上看成一块黑。切主题时会**连筛选区一起重排**（胶囊的 `--c / --ink` 是渲染时写死在内联样式里的，只重绘图表不会动它们），所以点一下深浅，那排「全部 / 餐饮 / 日常」的文字颜色当场就换，不用再点一次。

**社保** —— 总览倒数第二张整宽卡，标题就叫「社保」（原来那块「工资与五险一金」的牌子拆掉了），副标题改成一行实时摘要：`个人 ¥1,653.01 · 公司 ¥1,447.87 · 实发 ¥4,714.91`，左边四个字段改一格它就跟着重算。

| 字段 | 含义 | 默认 |
|---|---|---|
| 基数 | 社保 / 公积金缴费基数 | 8477 |
| 工资 | 税前工资 | 6400 |
| 绩效 / 补贴 | 参考项，只写在「实发」那行的脚注里 | 2425 / 550 |
| 差距 | 应发与实际到账的差（个税等杂项） | 32.075 |

五行缴费（养老金 8/0、公积金 7/7、医保 2/8.08、失业保险 0.5/0、补充公积金 2/2，格式是**个人比例 / 公司比例**）都带两个输入框，改比例或改基数，个人缴费、公司缴费、共计当场重算；下面是 **合计 / 应发（工资 − 个人缴费）/ 实发（应发 − 差距）**。默认这组数字算出来是 个人 1653.01、应发 4746.99、实发 **4714.91**，跟原始表格对得上。

排版整块重做过，为的是「一眼能读」：字段改成标签在上、数值在下（标签 11.5px 灰、数值 18px/780 等宽数字，下面垫一层 `--surface-2` 圆角片），一行四个不再挤成一串；表格 `table-layout: fixed` + 写死五列宽（项目 21% / 比例 31% / 个人 16% / 公司 16% / 合计 16%），比例那列的两个小输入框外包一层 `div` —— 之前 `td` 自己 flex 掉了，表格列会当场塌成一格，格子里的数也一并放大：正文 13.5px、项目名 14px/700。窄屏（≤760px）自动落回三列、表格可左右滑。

**表尾换成了一条三格摘要带**：原来 `<tfoot>` 里五列各塞一个数字，`table-layout: fixed` 下「¥1,083.00」被截成「¥1,083…」，读不出个位。现在 `tfoot` 整个撤掉，换成 `.pay-summary` 六列栅格（`#payFoot` 变成 `div`）—— 上半行三格 `个人合计 / 公司合计 / 缴费共计`（个人那格用 `--expense` 绿），下半行两格 `应发 / 实发` 各占 3 列（实发那格垫一层 `--income` 淡红底，数字 21px/800）。副标题同时写 `每年合计 ¥56,578.92 · 本月到手 ¥4,714.91`。三处数字口径一致：改基数、改比例、改工资，摘要带和副标题同一帧一起变。

**报销费用** —— 紧跟社保下面、单独一张整宽卡。表头右侧常驻合计（`¥385.50` 这种），下面是添加行：**日期按钮（默认今天）· 内容 · 金额 · 添加**，四个宽度写死 `156 / 1fr / 120 / 74`，四格都带小标签，回车即提交。

- 日期不再用浏览器原生的 `<input type="date">`（各家样式不一、还弹原生小窗）：换成一颗带日历图标的按钮，点开是**和记账弹窗同款的日历浮层** —— `.date-pop` 那套皮肤、月份网格可翻年翻月、今天带圆点、选中填主色，底部「回到今天 / 完成」
- **同一颗浮层服务所有日期框**：添加行一颗，列表每行也一颗。`gpOpen(anchor, value, cb)` 按锚点定位、自动避让视口下边界（放不下就翻到上面）、点外面 / Esc 关闭；记账弹窗那颗 `#datePop` 还在原位，两者互不干扰
- 列表一行一条：内容 → 金额 → **日期按钮**（点开改，改完立刻重排并重算合计）→ 删除
- 列表按日期倒序排，新记的这天排最上
- **删除按钮做成 30×30 的描边方块**（原来只是一个裸 ×，热区小得几乎点不到），hover 变红底红字，热区因此扩到整格
- 空的时候不是一句灰字，而是一个虚线占位块（`min-height: 124px`），卡片高度不会因为「还没记」而塌下去一半

所有改动双写：`localStorage` 留一份镜像（`qingzhang.pay.v1`，离线 / 刷新立刻可读），**同时写进 `state.store.pay`**，跟着云同步的 `state.json` 一起推 —— 换设备、换浏览器都拿得到同一组社保数字和同一份报销台账。老版本只存在 localStorage 的那份数据，第一次打开时会自动搬进 store（只搬一次），不用手动导出。云端的 `pay` 和本地不一样时会重画这两张卡；值一样就不动 DOM，每分钟轮询不会把你正在编辑的输入框重建掉。「恢复默认」把这组数字退回出厂表，也一样会推上去。

**自由排布**：13 个板块（一条四格信息带 + 7 张账本图 + 一条魔方数字带 + 2 张魔方图 + 社保 + 报销费用）全部落进一张 12 列栅格。点顶部「排列布局」进入编辑态 —— 拖板块左上角手柄换位置，拖右下角改宽高（3–12 列 / 2–18 行），拖到视口上下边缘自动滚屏，长距离搬运也够得着。排好点「保存布局」：写进 `localStorage` 的 `qingzhang.overview.layout.v1`，同时随云同步的 `state.json` 推到私有仓库，换设备自动拿到同一份排布。「恢复默认」回初始顺序，「复制布局代码」导出 JSON 交给 R 写进 `DEFAULT_LAYOUT` 就能固化成所有人的默认版。窄屏（≤940px）不排布，按保存顺序纵向单列展示。

`cubestats` 是一条卡、四扇门：卡内 `display:flex` 平分四格，格与格之间一根 1px 分隔线，每格「5px 主色圆点 + 小标签 / 21px 数值 / 一行口径小字」（「件魔方」「累计器材花费」「场 WCA / 自办赛」「累计报名支出」）。**四格全都能点**：前两格进魔方页的购买记录，后两格进比赛记录页；悬停整格提亮，键盘 Tab 也能进。**「魔方类型支出排行」不是饼图，是和高频项目 TOP 10 同一套横向柱** —— 12px 柱宽、右端 6px 圆角、从主色 32% 透明渐变到实色、右侧等宽金额，点一条跳到魔方页并按类型筛。年度趋势仍是面积折线，点年份跳到对应年份记录。这两处点击都走同一条 `jumpCube()`：先 `setView('cube')` 把 iframe 挂起来，再把 `{tab, year, type}` 用 `postMessage` 送进去（iframe 还没 `src` 时每 120ms 重试一次，最多 60 次），子页里的 `applyCubeFilter()` 落到筛选器上并重画列表。

要再调整，就在总览里排好、点「复制布局」，把 JSON 抄回 `DEFAULT_LAYOUT`，版本号顶一格 —— 这样老设备上残留的旧布局会自己作废。

**消费日历的滑杆长度是原来的三倍** —— ECharts `visualMap` 那条色带默认又矮又短，鼠标很难在上面精确定位。现在 `itemHeight` 从 130 拉到 **390**（条宽 12、`textGap` 10、字号 10），长度三倍，两头极值标签拉开了距离。中途试过把它加粗到 26 / 420 / 13px，那版太抢眼、还把日历格挤扁了，**已回滚**到这组细长参数，日历格子的 `bottom` 也退回 34。

**日历** —— 按 年 / 月 / 周 / 天 四种粒度看流水。

- 月视图 6×7 栅格，整页锁一屏，不出现纵向滚动
- 格子内条目按当日笔数自动分两档：行高够（≥34px）用两块式（名称在上、金额右对齐在下），被压扁时切单行式（名称 …… 金额）；行高按格子剩余高度均分，下限 22px、上限 48px，名称与金额统一 12.5px
- 溢出部分折成 `+N 笔`：**独占格子底部一整行**，铺满右下角 ＋ 左侧的整行宽度，与 ＋ 并列；条目仍按一行 2 个排满，不再为提示让出一个条目格
- **单击格子空白处弹「记一笔」，点条目直接改这一笔，双击进当日明细**：单击格子空白处（含 `+N 笔`）会在 **110ms** 后弹出记账浮层，日期已填成那一格 —— 判窗只比一帧长一点，落手几乎同时到。真正的双击靠两道兜底：判定窗内第二次 `pointerdown` 一落就先撤掉挂起的浮层（快双击全程不闪），万一是慢双击、浮层已经出来了，`dblclick` 里再把它收回（450ms 内只认「刚由这一格弹出」的那一个），然后 `jumpToDay` 跳「天」视图。年视图点某一天仍然是直接跳日。＋ 常驻可见，热区扩到 40px，单击也是记一笔
- **月 / 周视图里点条目 = 就地改这一笔，不再跳日页**：命中 `[data-id]` 就先 `preventDefault` 掉格子的单击链路，按 `dataset.id` 从 `allRecords()` 里取回原记录交给 `openModal(rec)` —— 冒出的是和天页同一颗「编辑记录」弹窗（内容 / 分类 / 子类 / 日期 / 金额 / 删除 / 保存修改），标题右边那颗胶囊写着 `2026 年 11 月 2 日 · 周一`，保存后当场重算当天、当月和所有图表。日历本身留在原粒度不动，回来还是刚才那一屏。空地说到底还是记一笔，两种手势现在互不抢
- **← → 翻页**：日历页按左右方向键等同于点那两颗箭头，年 / 月 / 周 / 天四种粒度各走一步（`shiftCalStep`）。弹层开着、焦点在输入框里、按着 Ctrl / ⌘ / Alt / Shift 时不抢键
- **滚轮翻页 = 连续滚动，不是淡入淡出**：鼠标停在哪块棋盘里就在哪块里滚，内容**跟着指针走**，下一页从另一侧同步顶上来 —— 两页同屏滑动，不是「画面闪一下换掉」。
  - 实现上给旧内容拍一张快照（`.soft-ghost`，`position:absolute` + `pointer-events:none`，按 `getBoundingClientRect` 贴住原位），真节点腾出来渲染下一页并先摆到框外；ghost 负责滑出去、真节点负责滑进来，`p` 就是滚动进度
  - **运动是弹簧，不是「每帧补一个比例」**：位置 `p` + 速度 `v`，每帧按 `a = ω²(goal − p) − 2ω·v` 积分（临界阻尼，不弹不过冲），子步长固定 1/120s，掉帧也不炸。**速度连续**才是丝滑的来源 —— 早先按「每帧补剩余距离的 20%」写，第一帧补得最多，一帧就是一百多像素，看着就是一耸；换成弹簧后每帧的位移变化是渐进的，起手柔、中段匀、末尾自己收力
  - **滚轮只改目标**：一格 `100px` 折 **1/3 页**（`SOFT_SPAN = 300`），连滚几格目标就叠多远，画面跟着加速追；停手 **150ms** 后结算，进度 ≥ **0.16** 或速度还往前冲（`v > .8`）就把这一页走完，否则原路退回 —— 慢吞吞挪两下不会误翻，鼠标一格必然翻页
  - **到站是吸附，不是停住**：`|goal − p| < 0.004` 且速度 < 0.12 时把 `p` 吸到目标上再判结果。少了这一步 `p` 会永远卡在 0.996 上，ghost 撤不掉、标题也不换（这个 bug 在真机上表现为「滑到 99% 就定住不动」）
  - **方向随粒度**：月历 / 年历 / 天页竖向（旧页往上出框、新页从下面顶上来），周历横向（旧页往左、新页从右）
  - **标题不抢跑**：`headSnap()` / `headApply()` 在拖动期间按住标题、笔数、空态浮层不动，交割那一刻才换 —— 不然滑到一半就报出下个月，很跳
  - **连滚排一页**：这一页已经排满（`goal >= 1`）时再来一格，记在 `queue` 上，交割完立刻 `softStart` 接下一页，中间不留空档 —— 快甩六格是两页，不是原地不动
  - **中途反向按「就近归属」**：`p < .5` 原路回上一页（顺手清掉攒下的连滚），过了半页就把这页走完
  - 交割后只锁 **46ms**（够挡同一个 notch 的重入，不掐后续滚轮）；`|deltaX| > |deltaY|` 认横向、否则认纵向，`deltaMode` 为行 / 页时先换算成像素（×16 / ×320），鼠标滚轮和触控板两个方向都吃得下
  - 弹层/确认框开着、日期选择器或报销日历浮层开着、鼠标在左栏表单里（`.day-side` 自己要能滚）时一律不抢滚轮
  - **手机上筛选默认折叠**：≤760px 时工具条多一颗漏斗按钮，`.ct-filters` 进来就带 `is-collapsed`（`display:none`），日历和下面的记账表单不会被那一排筛选挤走；点漏斗展开，点「记一笔」时再自动收回去。桌面端按钮不显示，还是两行筛选常驻
- **箭头 / `← →` 走同一套两页滑动**：`softStep()` 用 rAF 把进度从 0 推到 1（**430ms**，`easeInOutCubic`），扫过的就是同一对 ghost + 新页，所以键盘、按钮、滚轮三种入口手感一致 —— 箭头比滚轮「有主见」，但一样不硬切
- **年历一天双色**：一天只有支出是绿、只有收入是红、两样都有就斜切一刀（`linear-gradient(155deg, 绿 0 47%, 红 53% 100%)`），深浅都按当天金额占各自峰值的比例取（`.16 → .90`）；悬停提示写成 `2026-11-08 · 支 ¥120 · 收 ¥300`，每月标题右侧也从单个数字改成两条：`−¥1,234`、`+¥5,000`，只有一边有数就只显那一边。之前「筛选为收入时年历一片空白」其实不是没渲染 —— 那 25 个收入日都在，是**颜色全绿**，绿底上根本看不出收入，改双色之后一眼就能分

- 每个月表拆成四条：**早餐 / 午餐 / 晚餐 / 其他**（`早餐·午餐·晚餐 → 餐饮 / 三餐`，`其他 → 日常 / 其它`），金额以单元格为准；四栏全空但「当日消费」有数的那天，按一条「其他」记
- `2023.12.08` 的午餐那格是 `12..7`（录入笔误）、`2022.12.31` 是「共计」汇总行 —— 这类非数字格子跳过，不编数
- 体重列一并搬进 `weights`，只补「种子里还没有」的日期：新增 **332 条**（2022-08-29 → 2023-11-19），合并后总共 569 条，覆盖 2022-08-29 → 2026-10-25
- 总览「消费日历」右上角那排年份按钮原来是写死的 2024 / 2025 / 2026，现在按 `YEARS` 现场重建 —— 数据里有几年就出现几颗，补进 2022 / 2023 之后就是五颗

**「其他」列的批注已并进内容**：三份 xlsx 的 F 列共检出 382 个带批注的单元格（去重后），批注文字形如 `饮料+聚餐` / `护腕+腕托+口罩`，去掉作者的 `Lean:` 前缀后写进对应记录的 `note`，原来千篇一律的「其他」不再出现。分类 / 子类直接照 `app.js` 的 `SUBCATS` 关键词规则判：命中最长关键词的那一级分类赢，子类按表内优先级取第一个命中的；表里没收的服务类词（理发 / 洗澡 / 洗衣服 / 快递 / 车票 / 方便面等）用一张补词表兜底，落不进的留「其它」。同时写 `subExplicit: true`，保证以后编辑这条记录时不会被自动识别冲掉。按「日期 + 金额」精确配对，**270 条**成功改写；余下 112 条在账本里找不到同额记录（88 条来自 `2024账单.xlsx` 里另存的一份 2023 版本，25 条是 2024 年 1—2 月，账本目前只从 2024-07 起），没动原数据、没硬塞新账。

日历子类筛选行右侧新增金额统计：按当前粒度显示区间内该分类（含当前子类）的金额，年历显示「年统计」、月历「月统计」，周 / 日同理；子项按钮收窄，统计结果取 `rangeRecords()`，与按钮上的笔数同一口径。筛「全部」时子项按钮没有，但 chip 照留，显示当前区间的收支总额；再叠「支 / 收」筛选时金额跟着变，字色按账本口径走——支出绿 `--expense`、收入红 `--income`，「全部」用中性色。

**总览统计口径**：2024-07-01 之前的**支出**不进 KPI / 趋势 / 构成 / 排行 / 同比，收入不受影响；日历明细、当天列表、体重分析仍看得到那些老账。口径改在 `scopeRecords()` 与 `prevYearTotals()`，日历那几处仍走 `allRecords()`，所以「总览只看有效区间、日历保留全量」两边不打架。

单条记录结构：

```js
{
  id: 'a2024-0001',
  date: '2024-07-22', year: 2024, month: 7,
  type: 'expense',          // expense | income
  category: '餐饮',         // 餐饮 日常 交通 服饰 娱乐 收入
  raw: '餐饮/零食',          // 源表里的原始分类，保留以便回溯
  note: '午饭',
  amount: 23.5
}
```

源表的宽表格式已摊平：每两天一列（名称 + 金额）、行是分类，转成一条一条的流水。`共计` / `攒` / `每日统计` / `体重` 这类汇总行跳过，金额为 0 的格子丢弃；其中「体重」行单独抓出来喂给 `weights`。

子类的展示顺序由 `SUB_ORDER` 定死，不跟随数据出现顺序 —— 日常：房租 / 水电费 / 家居百货 / 酒店 / 电子产品 / 其它；娱乐：**魔方** / 比赛 / 电子产品 / 订阅服务 / 话费 / 人情往来 / 学习 / 其它。筛选胶囊和「记一笔」的子类下拉都按这个顺序排；记账时**内容**（原「备注」）命中某档的关键词（魔方、魔表、五阶、天马……）会自动建议归到那一档。

运行时新增的记账保存在 `localStorage`（键 `qingzhang.ledger.v1`），与种子数据合并展示，互不覆盖。

同一个 store 里另外挂了三份附属数据：`weights`（体重，按日期）、`layout`（总览排布，服务端 v1–v5 都收，前端只认 v5）、`pay`（社保那组数字 + 报销台账）。三份都走同一套白名单清洗 —— 数字要有界、比例 0–100、报销金额 > 0、日期必须是 `YYYY-MM-DD`，超界的条目在客户端和服务器两侧各丢一次，坏数据进不来。

## 云同步

不接后端时，数据只在本机浏览器的 localStorage 里 —— 换设备、清缓存就没了。面板里两种后端可选：

### GitHub 私有仓库（零服务器，推荐）

数据存进一个**私有**仓库里的 `state.json`（默认 `LeanSun/bill-data`），走 GitHub Contents API。每次保存就是一个 commit —— **git 历史就是全套备份**，随时能翻回任何一版。

1. 建（或确认有）私有仓库，如 `LeanSun/bill-data`
2. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token
3. Repository access 选 **Only select repositories** → 勾这个私有仓库
4. Permissions → Repository permissions → **Contents: Read and write**（在搜索框输入 contents 可以直接筛出来）
5. 生成后把 `github_pat_…` 粘进面板的「访问令牌」

注意两点：仓库必须是**私有**的，面板会拒绝连公开仓库；令牌只存本机浏览器的 localStorage，权限也只有这一个仓库，泄露了影响面有限，但还是别贴给别人。

### 自建服务器

接上 `server/` 之后多设备共用一份账。侧栏左下「云同步」→ 切到「自建服务器」→ 填地址与口令。

首次连接时如果云端已有数据，会给两个选项：用云端版本覆盖本地，或用本地覆盖云端。**不做隐式合并** —— 两边都改过时让你自己选，比悄悄合丢一条强。

接上之后：本地记一笔 → 1.2 秒防抖后自动推送；切回标签页、每分钟轮询各拉一次。冲突检测：服务器模式靠 `rev` 版本号，GitHub 模式靠文件 sha —— 基线对不上而你本地又有未推送改动，就会浮出二选一。

同一面板里还有「导出备份 / 导入备份」（整份 JSON）—— 换域名、换设备、防手滑都用它。GitHub 模式下导入替换后的旧版仍留在 git 历史里。

后端接口、部署方式（VPS + Caddy / Docker / 平台）见 [`server/README.md`](server/README.md)。

> 后端是单用户单口令的私人账本，不是多租户服务。放公网前务必配 HTTPS，并把 `ALLOWED_ORIGINS` 收敛到具体来源。

## 实现上的几处取舍

**主题切换不吃帧。** 早期版本用 View Transitions 的 `clip-path` 圆形扩散 —— 半径变化不是合成动画，每帧都要重新裁剪两张整页快照再光栅化，60fps 给不出来。现在改成单帧换色 + 一颗独立合成层的光斑（只动 `transform` / `opacity`），大面积元素的 `background-color` 过渡全部移除，侧边栏的 `backdrop-filter` 也去掉了。

**日历一屏。** `#view-calendar` 锁 `calc(100dvh - var(--topbar-h))`，`.cal-grid` 用 `grid-template-rows: repeat(6, minmax(0, 1fr))`。默认的 `1fr` 最小值是 `auto`，内容一多就撑破容器；改成 `minmax(0, 1fr)` 才真正等分。

**条目高度不写死。** 渲染两遍：先把条目全部写进格子，再量真实可用高度，按条数与列数均分出行高，条少时每条最高 46px，条多时压到 15px 为止。行高跨过 34px 自动从两块式换成单行式。

**同比口径。** 2024 只有下半年。拿全年比半年会算出 +160% 的假增速，所以任一边不足 12 个月就换成月均比，标签也写「月均」。

```bash
python -m http.server 8080
# 或
npx serve .
```

然后开 `http://localhost:8080`。

首次启动打印一串随机口令。开 `http://127.0.0.1:8787`，左下「云同步」填 `http://127.0.0.1:8787` 和那串口令。

### 本机部署（Windows）

不动命令行的话，两个脚本就够：

| 脚本 | 作用 |
|---|---|
| `start-ledger.cmd` | 双击启动。带日志窗口，关窗口即停；可改端口、口令、跨域来源 |

手机 / 平板在同一 Wi-Fi 下访问 `http://本机IP:8787`（启动日志会列出）。第一次绑 0.0.0.0 时 Windows 防火墙可能弹窗，允许「专用网络」即可。

## 魔方统计（独立子应用）

左侧导航第三项「魔方」是独立的魔方统计页：魔方统计、比赛记录、润滑油指南、数据与备份、更新日志五个页签。它以 iframe 嵌在账单站里，父页面只提供外壳和深浅色同步，不读写它的任何数据。

原来魔方自己的「总览」页已经拆掉，内容搬进账本的**总览页**：一条 `cubestats` 魔方速览清单（`[12,3]`，四行：收藏 / 支出 / 参赛 / 报名费，每行可点，点了带着筛选跳回魔方页。早期是四格并排，每格只有 1/4 卡宽，`¥6,073.29` 直接被省略号吃掉，所以改成竖排四行加两张图（`cubeyear` 年度购买趋势 `[6,5]`、`cubetype` 类型支出排行 `[6,5]`）。那边只 `localStorage.getItem('cubeLedger_v1')` 读一份数据，账本 store 完全不知道它的存在；魔方 iframe 写数据时浏览器发 `storage` 事件，这几张卡即时刷新。

**页面结构（v1.0.18 重排）**：顶部导航从「整条白条里的一排按钮」改成**一块独立的圆角矩形卡片**浮在页面底色上，底栏与下边框撤掉；筛选（搜索 / 类型 / 厂家 / 年份，比赛页是年份 / 省份 / 项目）从右侧栏搬到**列表上方**，排法与日历一致 —— 一行控件 + 右侧一枚「筛选 N 条 ¥金额」的统计胶囊，下方一行已选条件（没有条件时整行收起）。「魔方概况」那张卡撤掉，条数与金额并进筛选条；`不同型号统计` / `厂家分布`（比赛页是 `比赛年份分布` / `省份分布`）上移到右栏顶部。列表随之放大：行内边距 10→13px、字号 13→13.5px、型号列自适应，10 行连同表头与分页一屏读完。

**板块卡片化 + 自由排布（v1.0.20）**：v1.0.19 为了「首屏 10 行」把整页锁成 `100vh` 定高 flex，代价是页面焊死在视口上 —— 所有板块塞进一个大容器，四周只能留白，也挪不动。v1.0.20 换掉这套骨架：`html/body` 回到 `overflow:auto`，魔方页与比赛页各自变成一块 `.cb-board`（12 列栅格、`grid-auto-rows:44px`、`gap:14px`），筛选条、记录列表、两张统计卡各是**一张独立的卡**（`.cb-panel`）平铺在页面底色上，板块之间只剩一条栅格间隙。

排布可自行调整：点板块上方的「排列布局」进入编辑态，卡片出虚线框、左上角一枚拖动柄（换位置）、右下角一枚缩放手柄（改大小），手势与总览页那套完全一致 —— 拖动时幽灵块跟随光标，`elementFromPoint` 找落点，落点上/下插入由光标相对中心决定；缩放按栅格列宽与行高换算跨度。松手即写 `localStorage['cubeLedger_boardLayout_v1']`，刷新、切页、换天都还是你排的那一版；旁边「恢复默认」一键还原。**跨度通过 CSS 变量 `--cb-w/--cb-h` 下发**：老样式里还留着 `#cubes .cube-list-card{grid-row:1!important}` 这类硬编码定位，行内样式压不过 `!important`，所以由样式表里一条 ID 级规则读变量。

默认排布按「10 行刚好落在卡里」配平：筛选条 `[12,2]`、列表 `[8,11]`、右侧两张图 `[4,6]` / `[4,5]`（比赛页是 `[8,11]` + `[4,6]` / `[4,5]`；v1.0.21 起筛选条移出栅格，列表 `[8,12]`、两张图各 `[4,6]`，见下文）。为此把表格行高从 58 / 60px 收到 48px（标签 34 + 上下各 6 内边距 + 边线），表头内边距 13→6px，比赛项目芯片行 42→32px、芯片 34→28px，并把比赛表从钉死的 1094px 改成跟卡片同宽（项目列在芯片行里横滚）—— 这两处正是「第 10 行压在卡片下沿」的真正原因，不是窗口不够高。窄屏（≤900px）栅格退成单列纵向流，编辑手柄隐藏。

**图表跟着卡片重算**：魔方那两张图原先只 `echarts.init()`，没登记进统一的 `charts` 注册表 —— `resizeAll()` 只认表里的实例，所以拖布局 / 改分栏之后画布还是旧尺寸，轴标签和柱尾金额就顶着框边跑出去了。现在 `cubePaint()` 会 `charts[el.id] = chart`，`resizeAll()` 挂到窗口 resize 上，柱尾金额改用短格式（`¥983` / `¥1.2k`），两张图的 `grid` 都带 `containLabel: true`。

**日期只走日历（v1.0.20）**：新增 / 编辑记录里的日期框不再接受手输（`readonly`），点框任意位置直接弹日历 —— 以前那个 `onclick` 只做了 `input.focus()`，真正开日历的是右侧箭头，等于把「看着是一整块」的控件做成了两个热区。日历升到**三级**：顶部那颗药丸写着「2026 年 11 月」，点它 → 12 个月份网格（标题变「2026 年」），再点标题 → 年份网格（标题变「2020 - 2031」、4 列 × 3 行），选完逐级回落；左右箭头在日视图翻月、月视图翻年、年视图翻十二年。底部按账本那套改成「回到今天 / 完成」。另外把「窗口 resize 就关掉浮层」改成**只重新定位不关闭** —— 以前拖一下窗口，刚打开的日历会自己消失。

**单层页面 + 导航成卡（v1.0.21）**：上一版把板块拆成了卡，页面上却还留着两道多余的面：顶栏是一条横贯整宽的白色表面（卡片外的第二层），列表表格外面还套着一个带描边的盒子（卡片内的第三层）。这一版两道都撤掉 —— 顶栏只留内容（`background: var(--bg)`，无描边、无阴影、无毛玻璃），`#cubes .cube-tablewrap` / `#competitions .comp-tablewrap` 只保留滚动职责，描边 / 圆角 / 底色清零，表头色带直接落在卡片身上。整页现在是「1 层页面底色 + 一层卡片」。导航栏顺势独立成卡：17px 圆角、一条描边、一层比卡片默认值再深一点的阴影（页面底色和白卡只差一点点，不靠阴影分不开），和筛选条、记录列表同一套卡面语言。

**「还剩多少」怎么算（v1.0.39）**：这张卡（天页「关于这一天」第三张）两个口径，都能手算复核。以截图那组数为例：
- **本月剩余** `mLeft = monthBudget − mtd`。`mtd` 是**当前查看日期所在月、从 1 号到这一天**的支出合计（只算支出，不算收入）；`monthBudget` 是**前 6 个完整月**的支出月均——只累计「月支出 > 0」的月份再除以月数，历史上没记账的空月不参与平均；六个月全空时退回「本月已花 ÷ 已过天数 × 当月天数」的线性外推。截图里 `3,062.74 − 1,321.75 = 1,740.99`，进度条 `1,321.75 / 3,062.74 ≈ 43%`，读的是「这个月的额度用掉多少」。
- **今年结余** `yLeft = yInc − yExp`，就是当年真实赚下的钱（旧口径拿往年支出均值当预算，算出来只是「超没超」，已废弃）。进度条 `yExp / yInc`，读的是「收入花掉多少」，越低越省。
- 脚注 `收 10 万 · 支 3.3 万 · 存下 68%`：`compactY()` 把 ≥1 万压成一位小数（≥10 万取整），`存下 = (yInc − yExp) / yInc`。截图那组：收 103,771、支 33,207、存 70,564 → 68%。
- 两个已知的粗口径：月均不含当月（当月还没过完，进平均会把额度压低）；「万」是四舍五入后的显示值，占比是按原始数算的，所以可能出现「10 万 − 3.3 万 ≠ 70,564」的错觉。

- **风格统一**：CSS 设计令牌换成账本的浅 / 深两套（背景、卡片、边框、文字、主色、圆角、阴影），主题按钮切换时父页面用 `postMessage` 通知 iframe 同步换色
- **可独立打开**：页面右上角「新窗口打开 ↗」直接在新标签页打开 `cube.html`，布局和功能一样
- **视觉语言**：右上角不再写「本地优先 · 数据存在当前浏览器」，改成实际口径——连上仓库显示「浏览器缓存 + 私有仓库备份」，没连显示「临时模式 · 只显示本机缓存」（不再写「显示空账本」，因为本机确实可能有你自己记的东西）。整页换成账本那套圆角 / 细描边 / 轻阴影 / 字阶 / 输入框 focus 环，色相仍用魔方自己的蓝
- **年份底色在深色下也能看见**：行底色从「写进 `background-color` 的浅色值」改成 `--tint` 变量铺一层 `background-image`。深色主题下走另一条路：调色板里那些 `#f2f7ff` / `#fff7ed` 是近白马卡龙色，饱和度只有个位数，把亮度压到 15% 只会得到灰 —— 无论怎么调都是同一块泥色。所以按年份索引换一套**同色系暗版**（`YEAR_DARK_PALETTE`，亮度 14—20%，暗红 / 墨绿 / 棕 / 紫 / 靛），每年一支真正带色相的暗色带；用户自选颜色则保色相、饱和度提到 30—48%、亮度定 17%（`darkYearColor()`）。行悬停改用内阴影提亮，不再把底色刷掉
- **两张表一个表头**：`#cubes .cube-table thead th` 与 `#competitions .comp-table thead th` 用同一条规则（`--soft` 底、12.5px / 800、无文字阴影、`text-align: center` 逐列居中），浅色近黑 `#0f172a`、深色纯白 `#f2f6ff`。原版那条 `#compRows th` 选错了层级（`th` 在 `thead` 里，不在 `tbody#compRows` 内），所以深色下表头一直钉在 `#111827` 上，白底黑字看着像没切换主题
- **弹层动效补齐**：新增记录 / 新增比赛 / 年份颜色 / 自定义选项四个弹层原来靠 `display: none → flex` 切换：父层从 none 变 flex 与子层样式在同一帧重算，浏览器拿不到「上一帧」，`transition` 直接被跳过 —— 这就是「记一笔有动效、新增记录没有」的全部原因。现在遮罩常驻挂载、用 `visibility` + `opacity` 切换，和账本「记一笔」同一套 —— 遮罩 `rgba(10,16,30,.44)` + `backdrop-filter: blur(9px)` 从 0 过渡进来，面板 `translateY(26px) scale(.962)` 起、`cubic-bezier(.22,1.24,.36,1)` 弹上去，260—440ms
- **日期输入与「记一笔」对齐**：原来是「输入框 + 一枚 ▦ 方按钮」，现在是一整块 50px 圆角框：左侧日历图标、中间 `YYYY-MM-DD`（无边框、随整框 focus 环）、右侧实时显示「· 周二」，最右一枚展开箭头，点框内任意位置直接弹月历面板（`dateBoxClick()` → `Cal.open()`），不再需要去找右侧那枚箭头（原来那个 `Cal` 弹层照旧）。手输日期时星期同步刷新
- **魔方图标换成 cuberoot 那套（自托管）**：`cuberoot.me/zh/icon` 用的就是 `github.com/cubing/icons` 这个上游，所以直接把 `@cubing/icons` 的 webfont 收进仓库 —— `assets/cubing-icons.css` + `assets/cubing-icons.woff2`（7.7KB，只带实际用到的字形），`<link>` 从 `cdn.cubing.net` 换成同目录。种类按钮、比赛项目胶囊、类型支出排行的项目名、自定义选项列表里的 `▦ / ◇` 占位全部换成真正的 `eventIcon()` 字形：333 是一格格方块、skewb 是斜切、clock 是表盘、pyram 是三角、sq1 是斜方，一列扫下来形状就能认出项目。顺带离线 / 内网也画得出来，不再等 CDN
- **厂家标识先出文字，图到了再盖**：`BRAND_LOGOS` 那四张图（魔域 / 魔方格 / 奇艺 / GAN）是远程 PNG，加载一旦失败或者 `loading="lazy"` 根本没触发，格子里就只剩一个空胶囊。现在结构是 `<em class="brand-fallback">厂家名</em>` 打底、`<img onload=…is-loaded>` 盖上去：图成功才显示图并垫一层浅色底板（深色主题下深描边 logo 也看得清），失败就 `this.remove()` 退回那句文字，永远不会空
- **深色模式收口**：原版样式表里有一批 `#id .class` + `!important` 的浅色硬编码（表头 `#111827`、库存表 hover `#f4f7ff`、雷达图底板 `linear-gradient(#fbfcff,#f5f8ff)`、润滑油的 `.lube-map` / `.lube-compare` / `.metric-chip` 白底、`.lubcard` 的 `#fff` 卡片），权重大过 `html[data-theme="dark"] .class`，所以深色下会冒出一块块白。修法分两层：**CSS 层**把前缀换成同样带 id 的组合压平权重再改成令牌（`--card` / `--soft` / `--line` / `--ink`）；**运行时层** `harmonizeDark()` 在每次重绘后扫一遍仍未收口的部件，把 alpha > .35 且三通道都 > 185 的底色换成 `rgba(255,255,255,.045)` 的薄高光，切回浅色时按 `data-hm-light` 标记原样撤掉。图表侧另有一套：`fade()` / `CT()` / `ctOpt()` 统一从 CSS 变量取轴线、分隔线、标签、图例、tooltip 底色，`backgroundColor` 一律 `transparent`，主题一变 `renderAll()` 整页重画而不是只 resize —— 画布才不会留在旧配色上
- 依赖：ECharts 用项目本地 `assets/echarts.min.js`，cubing 图标字体也自托管在 `assets/`（`cubing-icons.woff2`），整页零外链；唯一的外链是那四张厂家 logo（挂了会自动退回文字）

## 数据说明

公开仓库（本仓库 / GitHub Pages）里**没有任何真实流水**；种子数据只存在私有仓库 `LeanSun/bill-data` 的 `private-data.json`，读它需要该仓库的有效访问令牌。分享站点链接给别人：没令牌 → 空账本；把人加进私有仓库并把令牌填进「云同步」→ 刷新一次就能看到你的数据。断开连接或令牌失效时，`sync.js` 会调 `QZPrivate.dropIfActive()` 并刷新页面，内存里那份私人数据当场丢掉。

令牌只留在浏览器 localStorage 的 `qingzhang.sync.v3`，不写进仓库、不写进页面源码。要更新账单数据，更新私有仓库里的 `private-data.json` 即可，公开站点不用重新构建。

起因：反映「打开网址慢」。实测定位到不是代码问题，是 GitHub Pages 到国内的链路本身被限速。

1. **先量出来，再动手**。`curl` 分段计时 5 轮：DNS 与 TCP/TLS 几乎不耗时，慢在后半段。`app.js`（283KB）下载用了 **23.5s**，`styles.css`（113KB gzip）**31.3s**，`boot.js` 甚至只有 **1.6 KB/s**。首字节 TTFB 在 0.9s~4.1s 之间来回跳，同一份资源忽快忽慢。首屏合计约 560KB（gzip 后），按这个吞吐要 **50 秒以上**。
   横向对比同一台机器的其他链路：Netlify 0.33s 稳定、腾讯云 COS 0.17s、Cloudflare 边缘 0.65~1.26s、Vercel 3.1s、**Cloudflare Pages 的 `*.pages.dev` 实测 12.4s**。结论：换托管是最彻底的解法，但本次先做不改托管的部分。
2. **新增 `sw.js`（离线加速层）**。策略分三类，关键是**页面本身不缓存**：
   - 带 `?v=` 的资源（js/css）→ **缓存优先**。版本号变了 URL 就变，天然不会读到旧文件，这也是项目原有的版本号机制第一次真正被用上。
   - 页面导航 → **网络优先，失败才回退缓存**。刻意不给它设超时，宁可多等几秒也绝不让「改了版本号却看到旧页面」重演；断网时仍能打开记账。
   - 其余同源资源（无版本号）→ **先给缓存，后台顺手更新**。
   另设了 6MB 单条上限，并显式跳过 `cube-history.js`：那份 18MB 的魔方历史快照只在实际点开时直连下载，不进缓存，免得白白占掉配额。
   注册代码在 `index.html` 底部，只在 `https:` 下启用，本地 `file://` 打开不受影响。
3. **echarts 按需裁剪**。全站只用了 `line` / `bar` / `heatmap` 三种图（`dataset` 与 `title` 组件零引用，已核对），于是用 esbuild 只打包这三种图 + `Grid/Tooltip/Legend/MarkLine/DataZoom/VisualMap/AxisPointer/Graphic` 八个组件 + Canvas 渲染器：**1007KB → 611KB**，gzip 后 **326KB → 203KB**，省下约 123KB 传输（约 12 秒）。
   验证方式：无头 Chrome 渲染三种图 + 渐变 + `visualMap` 色条，输出 `RESULT=PASS`；`echarts.graphic.LinearGradient`、`getInstanceByDom`、`resize` 均保留。
4. **缓存策略的行为验证**。用 Node 模拟 `caches` / `fetch` 跑 `sw.js`，6 项全过：带版本资源首次联网、二次命中缓存不重复下载、换版本号后重新联网、页面导航走网络、断网回退缓存、无版本资源优先返回缓存。
5. **`echarts.min.js` 补上 `?v=`**。原先两页引用它都没带版本号，走不到缓存优先分支，每次都会后台重拉 203KB。现已随 `ASSET_V` 一起版本化。
6. **预期效果**：首次访问 50s+ → 约 35s（echarts 省下的部分）；**之后每次**静态资源全部命中本地缓存，只剩页面本身走网络，约 3~6s。彻底解决仍需换托管，方案与实测数据见本节第 1 条。
7. **回滚方式**：删掉 `index.html` 底部的注册块并清空浏览器站点数据即可退回 v1.5.1 行为；echarts 单文件可从 git 历史取回。

## v1.6.0 · 社保卡重做：按工资条闭环（2026-11-22）

依据《工资·社保·个税对账单（2026 年 10 月）》重做总览页的社保卡。原卡片不是「不好看」，而是**账算错了**。

### 一、旧版错在哪

| 项 | 旧版 | 工资条 |
|---|---|---|
| 应发 | 用 `工资 − 个人缴费` = 4,746.99（方向反了） | 工资 6,400 **+** 津贴 550 = 6,950.00 |
| 实发 | 4,714.91 | **5,256.06** |
| 绩效 | 2,425，**从不参与任何计算**，只出现在小字里 | 无此项 |
| 差距 | 32.075，一个用来凑数的补丁值 | 已查明是**工会会费 32.00** |
| 基数 | 8,477（四舍五入） | 8,476.51 |
| 单位比例 | 养老 0%、失业 0%、医保 8.08% | 16% / 0.5% / 9% |
| 公积金 | 593.39（按分算） | **593**（元以下四舍五入） |

关键漏洞：旧版没有个人所得税和工会费这两笔，实发与银行流水差 541 元（就是那笔没算进去的津贴）。

### 二、新版怎么算

```
应发   = 基本工资 6,400 + 交通津贴 550          = 6,950.00
五险一金 = 养老 678.12 + 医疗 169.53 + 失业 42.38
          + 公积金 593 + 补充 170               = 1,653.03
扣除   = 五险一金 1,653.03 + 个税 8.91 + 工会费 32.00 = 1,693.94
到手   = 6,950.00 − 1,693.94                    = 5,256.06  ✓ 与流水一致
```

**取整口径**是这次才理清的一处细节：社保按分记账，公积金按「元以下四舍五入」。所以医保 169.5302 记 169.53，补充公积金同一个精确值记 170 —— 不是哪边算错了。每行因此带一个 `r: 'cent' | 'yuan'` 标记。

**单位缴费**取上海 2026 口径（养老 16%、医疗 9% 含生育、失业 0.5%、公积金 7%、补充 2%）。交叉验证：公积金单位 593 + 170 = 763，与对账单里「单位汇缴 1,186 = 593×2、340 = 170×2」完全吻合。

**到手拆两笔**：工资 4,714.97（扣五险一金与工会费）+ 津贴 541.09（个税从津贴中代扣）= 5,256.06，与两笔到账对得上。

### 三、界面结构

1. **到手区**：标签 + 进度条（到手占应发 75.63%）→ 大数 ¥5,256.06 → 两笔到账 → 分隔线 + `应发 / 扣除` 两端对齐。
2. **输入区**：缴费基数、基本工资、交通津贴、个人所得税、工会会费，五格均可改，改完立刻重算。五个比例（个人/单位）也都能改。
3. **明细表**：五行五险一金 → `五险一金` 小计（带合计比例 19.5% / 34.5%）→ 个税、工会费两行（标「累计预扣」「工资 5‰」）→ `扣除合计`（标「占应发 24.37%」）。
4. **公积金条**：每月入账 1,526（单位 763 + 个人 763），一年 18,312 —— 这是唯一「单位缴的钱也进你账户」的部分，单独拎出来。
5. **脚注**：解释为什么扣款看起来偏高（基数 8,476.51 高于当月应发 6,950，因为基数按上年度月平均工资性收入核定）。

### 四、数据迁移

`pay` 加了 `v: 2` 结构版本号。旧数据（`base/wage/perf/subsidy/gap` + 五行旧比例）读取时自动搬家：

- `base === 8477` → 升级为 8476.51（这是旧版出厂值，不是用户改的）

## v1.6.10 · 数字滚动计数 / 默认布局定版（2026-11-22）

### 数字入场：之前方向完全错了

连续几版都在改 CSS 的上浮淡入（`numRise`），但用户说的「数字入场」其实是**数字本身滚动计数**。而且项目里本来就有 `animateValue()` 做这件事——真正的 bug 是：

```js
var prev = Number(el.dataset.value || 0);
if (Math.abs(prev - target) < .005) { el.textContent = formatter(target); return; }
```

第二次进总览时 `data-value` 已经等于目标值，`prev === target` 直接 return，动画根本不跑。所以用户只在前一次看到过一次滚动，之后「没生效」。

**修复**：给 `animateValue` 加 `force` 选项，切页渲染时强制从 0 重播：
- KPI 四张卡：**2s**，分别延迟 0 / 90 / 180 / 270ms 错峰
- 天页洞察小字：新增 `rollSmallNumbers()`，从文本解析数值和前后缀，**0.62s** 快滚；只在洞察区 DOM 真重绘时播（`data-static` 复用时不重播，避免筛选闪烁）

同时把之前所有上浮动画的 CSS 和函数（`numRise` / `replayNumIntro` / `replayInsights` / `nums-in`）彻底清除。

### 默认布局定版

按用户给的 JSON 固化 `DEFAULT_LAYOUT`：order 18 项不变，`salary:[6,15]`、`reimb:[6,7]`，版本 v13→**v14**，让已存的旧布局自动失效回落到新默认值（用户确认升级）。

Node 校验：生成的对象与用户给的 JSON `JSON.stringify` 完全一致。

## v1.6.13 · 折线去分段 / 2.5s 缓停 / 洞察读数与进度条（2026-11-22）

1. **折线为什么分段**：v1.6.12 用 `stroke-dasharray + getTotalLength()` 做从左向右描边。但 KPI 的 SVG 是 `preserveAspectRatio="none"` 加上 `vector-effect: non-scaling-stroke`，`getTotalLength()` 返回的是 viewBox 坐标里的长度，实际渲染被横向拉伸了好几倍——dash 走完就没得画了，于是折线断成几截。改用 `clip-path: inset(0 100% 0 0) → inset(0 0 0 0)` 直接裁整张 SVG，与路径长度无关，折线和淡填充都连续。

2. **数字尾段再放缓**：缓动从 quartic 提到 quintic（`1-(1-t)⁵`），时长 2s → **2.5s**。折线与储蓄率比例条同步改 2.5s，缓动统一 `cubic-bezier(.16,1,.3,1)`。

3. **「还剩多少」卡里的数字和进度条不动**：根因是选择器漏了。之前只滚 `.ins-key`（卡片标题旁的小字），而卡内真正显眼的三个数字用的是 `.ir-line b`，三条进度条是 `.ir-bar i`——两类都没被选中。新增 `animateInsights()` 统一处理：
   - `.ir-line b`（过往对比 / 本月剩余 / 年度结余）：2.5s，间隔 140ms
   - `.ins-mtd > b`：2.5s
   - `.ins-key`：0.9s（小字快一点，形成层级）
   - `.ir-bar i / .ins-prog i / .tb-track i`：从 0% 起 2.5s，间隔 90ms

   另外从别的视图切回日历·天时，若洞察区走了 `data-static` 复用（没有重绘），会补播一次，与 KPI 每次切回总览重播保持一致。筛选时不重播，避免闪烁。

**验证**：`strokeDasharray` 零残留、`svg clip-path` 2.5s transition 写入、三条进度条 `width 2500ms` transition 写入、`ir-line b` 捕获到文本变更；截图确认折线连续无断口；`errs=[]`。
